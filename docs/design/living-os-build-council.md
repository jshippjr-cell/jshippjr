# Living-OS Build — Council Reviews
*The executive council reviews each build phase. Same room as the STUDIO LIGHT
council; same rule: nobody is agreeable. Rulings bind the next phase.*

**The law under review:** every page carries ≥1 living element that cannot exist
in print; motion communicates state, confidence, automation, or intelligence —
never decoration. Everything serves: *Chordential is the operating system where
creative campaigns become production-ready.*

---

## Phase 1 review — foundation (live.js + lv-* grammar + machine beacon)

- **Marcus (Product):** "The beacon is the right first move *because it can say
  'machine idle.'* An honesty-capable indicator is worth ten animations. But a
  beacon is ambient — Phase 2 must make liveness *causal*: I act, the system
  visibly thinks, something changes. Don't ship another passive glow."
- **Dana (Brand):** "Approve the grammar, watch the dose. `lv-halo` on more than
  one thing per screen and we're a casino. Ratify: **halo = the one thing that
  changed; veil = only during real work.**"
- **Ellis (Design):** "The veil's propagation path is generic text tokens. In
  Phase 2 the tokens must be the REAL path (source → Intelligence → the modules
  actually touched), or it's theater."
- **Priya (Revenue):** "None of this is client-visible yet. Fine — operator
  first. But the count-to primitive must never animate a number that didn't
  change; a buyer who catches a fake tick never trusts a real one."
- **Theo (Chair) — binding:** Phase 1 accepted. Rulings for Phase 2:
  (1) thinking veil runs strictly for the duration of the real request — no
  minimum-duration padding for drama; (2) the propagation tokens name the real
  modules; (3) arrival choreography touches only elements the server reports as
  changed; (4) the no-JS path stays fully functional.
